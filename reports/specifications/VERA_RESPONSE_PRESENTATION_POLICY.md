## 1. Executive Mandate

All conversational and structured responses generated by the VERA platform must conform to this **Response Presentation Policy**.

In enterprise network management (NMS), operators rely on VERA for mission-critical diagnostics, incident isolation, and configuration changes. Misleading responses, leaked runtime metadata, synthetic numbers, or unstructured walls of text degrade operational velocity and undermine trust.

---

## 2. Core Presentation Principles

### Principle 1: Narrative-First Hierarchy
Every response must commence with a concise, authoritative operational verdict in **Block 0** before any charts, gauges, or tables are rendered.
- **Rule:** The narrative must summarize the state of the network or answer the user's specific question within 1–3 clear sentences.
- **Forbidden:** Never open a response with a raw Markdown table, command output dump, or empty visual container.

### Principle 2: Strict Data Authenticity & Zero Hallucination
- **Rule:** VERA must render **only** empirically verified values retrieved from network hardware, APIs, or database queries.
- **Forbidden:** Never fabricate placeholder values (e.g., displaying `0% CPU` or `10ms latency` when an SSH connection failed). If a metric could not be retrieved, state explicitly that the metric is unavailable or unreachable.

### Principle 3: Anti-Decoration
- **Rule:** Every visual component (gauges, hop lines, diff viewers) must serve an informational or interactive purpose directly relevant to the user's request.
- **Forbidden:** Never generate decorative graphs, frivolous charts, or visual clutter that does not add diagnostic value.

## 3. Tool Metadata Sanitization Engine (`_sanitize_narrative`)

Conversational models frequently leak internal runtime markers into text outputs. The VAE `ExperienceComposer` enforces an automated sanitization pass over every narrative before rendering:

```python
def _sanitize_narrative(self, text: str) -> str:
    cleaned = text
    # 1. Purge tool invocation counters: e.g. [1 tool digunakan svg], (2 tools used)
    cleaned = re.sub(r"\[?\d+\s+tools?\s+(?:digunakan|used)[^\]\n]*\]?", "", cleaned, flags=re.IGNORECASE)
    
    # 2. Purge raw tool call artifacts and JSON blocks
    cleaned = re.sub(r"```(?:json)?\s*\{\s*\"tool\"[^\}]+\}\s*```", "", cleaned, flags=re.DOTALL)
    cleaned = re.sub(r"```(?:json)?\s*\{\s*\"name\"[^\}]+\}\s*```", "", cleaned, flags=re.DOTALL)
    
    # 3. Purge orphaned tool execution markers
    cleaned = re.sub(r"^tool\s*:\s*\w+.*$", "", cleaned, flags=re.MULTILINE)
    
    # 4. Normalize excess whitespace
    cleaned = re.sub(r"\n{3,}", "\n\n", cleaned)
    return cleaned.strip()
```

### Sanitization Rules Matrix
| Artifact Pattern | Example Leakage | Sanitization Action |
| :--- | :--- | :--- |
| **Tool Counter** | `[1 tool digunakan mikrotik_get_resources]` | Completely stripped from narrative |
| **Raw JSON Tool Result** | ````json {"success": true, "interfaces": [...]} ```` | Stripped from narrative; parsed into structured VAE blocks |
| **Prompt Residuals** | `Silakan isi formulir di bawah ini jika ingin melanjutkan.` | Retained only when an active form is present; removed if obsolete |
| **Internal Trace Tags** | `<thought>...</thought>`, `[internal_debug]` | Stripped at runtime gateway |

## 4. Tone, Terminology & Localization Standards

1. **Language:** Professional Indonesian with standard international networking nomenclature (e.g., *interface, throughput, gateway, subnet, BGP peer, hop, latency, packet loss*).
2. **Clarity:** Active voice, precise metrics with explicit units (e.g., `14% CPU`, `54.2 MiB`, `1.2 ms`, `1 Gbps`).
3. **Error Reporting:** Objective and non-blaming. When an error occurs, state the technical fact clearly (e.g., *"Koneksi SSH ke 192.168.0.1 port 22 ditolak oleh host"*) and immediately present recovery options.
