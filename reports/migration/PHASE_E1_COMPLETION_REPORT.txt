1. EXECUTIVE SUMMARY & ROOT CAUSE ANALYSIS
--------------------------------------------------------------------------------
During the Phase E audit, the system suffered from a critical authentication bug:
opening the Client Site immediately treated any visitor as 'lingga_admin', the
login page never appeared, and logging out either retained the session or
immediately bounced back to 'lingga_admin'.

Investigation identified five compounding root causes:
1. Hardcoded UI Identity:
   AIRA_ECOSYSTEM/app/frontend/src/components/Sidebar.jsx hardcoded the bottom-left
   profile pill with the initial 'L' and label 'Lingga' unconditionally.
2. Incomplete Frontend Auth State Lifecycle:
   The frontend lacked a first-class Guest state. Any unauthenticated page load
   fell back to default profile mocks or stale localStorage artifacts without
   evaluating session validity against the backend.
3. Client-Only Logout Without Server-Side Revocation:
   Clicking 'Sign Out' in AccountProfileModal cleared localStorage but did not
   revoke the session token hash in 'operational_user_sessions'. Stale tokens or
   cached interceptor state could immediately restore the session.
4. Missing Unauthenticated Boundary on Control Plane:
   AdminPlatformPage did not enforce client-side or router-level access guards.
   Unauthenticated visitors could view administrative layout containers before
   any API call failed.
5. Absence of ChatGPT/Claude-Style Guest & Quota Tiering:
   There was no differentiated guest persona with scoped token limits, automatic
   periodic resets, or prompt preservation across authentication challenges.

All root causes have been resolved. The authentication flow, guest onboarding,
session revocation, and ChatGPT/Claude-style token quota governance are now
fully integrated and verified.

3. BEFORE & AFTER WORKFLOW COMPARISON
--------------------------------------------------------------------------------
A. First-Time Visitor (Client Site):
   BEFORE: App opened automatically logged in as 'lingga_admin' with Superadmin rights.
   AFTER:  App opens in Guest Mode. No account injected. Sidebar shows 'Guest User'.
           Visitor can immediately test AIRA prompts within guest quota limits.

B. First-Time Visitor (Admin Site):
   BEFORE: Admin Control Plane opened immediately without requiring credentials.
   AFTER:  AdminLoginPage appears. Access to Control Plane is strictly blocked until
           authenticated as an administrator (PLATFORM_SUPERADMIN or PLATFORM_SUPPORT).
           Customer users attempting to log in on Admin Site are rejected with 403.

C. Logout Operation:
   BEFORE: Clearing localStorage caused the UI to reload or fall back to 'lingga_admin'.
   AFTER:  Calling /api/v1/auth/logout revokes the session token hash in the database.
           AuthContext transitions to LOGGING_OUT and then GUEST.
           Sidebar and Workspace return to clean Guest mode. Old bearer token is invalid.

D. Token Quota Exhaustion & Prompt Preservation:
   BEFORE: Requests crashed or threw generic errors; user prompt draft was lost.
   AFTER:  When guest quota is exhausted, backend responds with 403 LOGIN_REQUIRED.
           Frontend displays 'LoginRequiredModal' and stores the prompt draft in
           sessionStorage and AuthContext. After login or quota grant, user resumes
           without retyping their technical prompt.

5. CHATGPT / CLAUDE-STYLE TOKEN QUOTA GOVERNANCE
--------------------------------------------------------------------------------
Architecture Dimensions:
1. AI Model Tokens:
   Raw LLM input and output tokens metered atomically per inference request.
2. User Usage Quota:
   Periodic limit assigned to a user or guest based on their subscription tier.
   Supported reset periods: DAILY, WEEKLY, MONTHLY, CUSTOM.
3. Internal Operation Credits:
   Cost accounting for tool execution and playbook actions.

Reset Policy & Timezone:
- Standard Timezone: Asia/Jakarta (WIB / UTC+7).
- Next Reset Calculation:
  * Calendar Monthly: Aligns to 1st of the next month at 00:00:00 WIB.
  * Rolling Monthly: Exactly 30 days from period start.
  * Daily: Aligns to next calendar midnight at 00:00:00 WIB.
- Rollover Logic:
  * When reset_date is reached, 'used_tokens' is reset to 0.
  * Quota ceiling is refreshed to the active tier limit.
  * Historical ledger records in 'operational_token_ledger' are NEVER wiped or altered.

Superadmin Token Controls:
- Manual Quota Override: Allows platform superadmin to set custom quota ceilings.
- Bonus Grants: Grants one-time token injections without shifting subscription tier.
- Instant Reset: Resets a user's used_tokens back to 0 immediately.
- Tamper-Evident Audit Trail: Every modification logged to 'operational_token_quota_adjustments'.
