# AIRA OS — Phase Networking III
# Topology Foundation & Multi-Device RCA Specification

## 1. Executive Summary

This document specifies the integration of topology relationships into root cause analysis (RCA), delivered under Work Package N3.7 of Phase Networking III.

Traditional single-device diagnostic tools treat anomalies on a router in isolation. AIRA OS Phase Networking III links adjacent routers and transit paths, enabling the diagnostic engine to identify when a local outage (e.g. "Klien tidak dapat menjangkau internet") is actually caused by an upstream dependency failure (e.g. "Transit router upstream kehilangan default route").

## 2. Multi-Device Investigation Architecture

### 2.1 Investigation Orchestration Flow

```
[Operator Input]
  - primary_device: "Core-1"
  - related_devices: ["ISP-1", "Edge-2"]
  - symptom: "Client cannot access internet"
       |
       v
[MultiDeviceEvidenceOrchestrator]
  - Collects interfaces, routes, IP, ARP across all targets
       |
       v
[CrossDeviceEvidenceCorrelator]
  - Identifies links, next-hop routers, mutual subnets
       |
       v
[Upstream Dependency Analyzer]
  - Finds default gateway of primary device
  - Matches gateway IP to related devices
  - Inspects upstream device's routing table & WAN health
       |
       +---> [If upstream missing 0.0.0.0/0 route]:
       |       Generates RankedHypothesis: "Kegagalan Dependensi Upstream" (HIGH confidence)
       |
       +---> [If upstream healthy]:
               Generates RankedHypothesis: "Masalah Segmentasi/NAT lokal" (MEDIUM confidence)
       |
       v
[Persisted IncidentRecord]
  - Stored in network_intelligence.db
  - Includes multi-device facts, correlation ID, limitations disclosure
```

### 2.2 Truthful Uncertainty Disclosures

Every multi-device diagnostic report generated by `run_multi_device_investigation()` includes mandatory disclosures:
- Discloses that observations represent a point-in-time snapshot.
- Discloses when intermediate L2 switches or ISP transparent middleboxes could not be directly observed via SSH.
- Recommends non-destructive active verification tests before executing changes.
